## 3. 选用顺序与跨组件规则

1. 搜索本目录和当前业务域组件。
2. 结构、交互和无障碍语义一致时直接复用 `implemented` 组件。
3. 仅缺少通用变体时，先补测试，再扩展公共组件。
4. 含业务状态机、角色、权限或接口语义时，放入业务域。
5. 只出现一次且没有稳定接口的布局留在页面内部。

- 主题、颜色、间距和状态使用项目语义 token。
- 用户可见文案遵循项目国际化策略。
- 公共组件通过 props、children、slot 或等价机制接收内容，不直接请求业务接口。
- `planned` 可指向尚不存在的未来目录，但必须写明规划依据和落地条件。

## 5. 新组件检查清单

- 是否已有组件覆盖至少 80% 的结构与交互？
- 是否能通过通用变体扩展，而不是复制实现？
- 是否不含角色、接口和状态机等业务耦合？
- 是否使用项目语义 token、资产、国际化和统一焦点样式？
- 是否先增加组件测试，并同步更新本目录和示例？
