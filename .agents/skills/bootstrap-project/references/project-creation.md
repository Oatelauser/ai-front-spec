# 在当前仓库搭建前端工程

适用于用户要求基于本模板创建前端应用、而当前尚无可运行工程的任务。初始化规则和创建工程是同一开发任务中的不同步骤，默认都在当前项目根目录完成。

## 1. 判断已有工程与已定选择

检查 `package.json`、锁文件、框架配置、源码、运行时及 CI。已有工程时沿用现有栈，不重新运行脚手架。仅有 `.agents/`、`resources/` 和说明文件属于尚无业务工程；不能因为目录非空而另建永久业务目录。

采用用户已选框架、语言、包管理器和产品目标。未决定且仓库无法回答的关键技术选型，给出具体推荐及影响再询问；等待时可完成通用规则和文件影响调查。框架未确定时使用 generic 画像草案，不把 React/Vue 模板预设当成已安装事实。

## 2. 在非空根目录创建

1. 先列出要创建和可能冲突的文件，保护 `.agents/`、`resources/`、根 `AGENTS.md`、说明、历史记录和用户修改。
2. 优先使用支持保留现有文件的官方脚手架或按其可靠模板创建。不要选择清空目录、强制覆盖或删除现有文件的选项。
3. 脚手架要求空目录时，可在本次临时暂存目录生成，然后比较并将工程文件合并回当前根目录；暂存目录不成为业务工程的最终位置。只清理本次创建的暂存目录。
4. `package.json`、配置、`.gitignore` 等冲突逐项合并，不以脚手架示例替换已有测试、命令或团队规则。源码目录服从所选框架，不固定为 `src/`。
5. 在当前根目录安装已选业务依赖，保留一种已确认的包管理器与锁文件；能力插件安装另按其授权范围处理。

## 3. 更新事实并继续实现

从实际产物核对版本、入口、源码目录、启动、构建及已存在的测试命令，更新 `docs/PROJECT_PROFILE.md`、根 AGENTS 与适用配置。规则草稿不会阻止已有授权下为补齐这些事实而创建工程；高影响业务决定未确定时只限制依赖它的实现。

接着按 frontend-task 完成用户页面或流程。验证启动及目标路由、适用质量命令、浏览器交互和支持视口，交付可访问 URL。仅脚手架首页能运行不能证明业务需求完成；仅规则校验通过不能证明工程可运行。

用户只要求更新模板、说明或规则时，不自动执行本流程，不凭空生成示例业务项目。
