# 画像选择

先读取目标 `docs/PROJECT_PROFILE.md`，存在时以其为基线，逐字段补充，不自动重建。首次初始化时始终读取 `resources/toolkit.json` 的 `profiles`，逐项检查模板是否存在且可读，并展示所有可用候选（通常为 generic、React、Vue）；不得因为仓库没有框架证据而隐藏候选。用户此前明确提到的框架或模板只能作为预选项和推荐依据，不能替代本次初始化确认。模板重构或迁移需要用户明确选择。

不存在时，候选来源以 `toolkit.json` 为准，文件系统扫描只用于报告清单与实际资源的不一致。没有工程事实时可以推荐 generic，但 `recommended` 不等于 `selected`：用户必须选择 generic、React、Vue 或明确暂缓。暂缓时保留 `templateSelection=pending`，只生成不带模板预设的最小画像骨架；不能把 generic 草案写成已选择的模板。仅有模板资源、尚无工程的目录不得推断运行时或质量命令；已授权创建工程时先记录草案，创建后依据实际配置更新，不要求全部工程事实先于工程存在。

模板选择后，继续读取所选模板的真实字段，针对版本、语言、目录、构建/启动命令、路由、依赖和其他高影响缺口按确认流程提问。模板文件缺失或不可读时报告具体缺口，不用 generic 或相似文件冒充。

模板选择不代表批准其全部预设。React/Vue 模板的依赖、路径、图标、主题、语言和命令均须对照目标事实；不匹配项列入字段差异。非前端项目可以使用 generic 并明确不适用项，不能用单个手机尺寸代替多端范围。

输出：画像来源、证据文件、现有画像处理策略。模板缺失或来源不可读时报告缺口，不用相似文件冒充。继续读取 [字段与证据](profile-schema.md)。
