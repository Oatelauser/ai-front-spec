# 确认流程

先完成仓库调查、逐字段推荐和文件差异，形成可审阅结果。已有用户要求和本会话授权继续有效，不重复请求同一确认；缺失的高影响决定、冲突字段和整体替换决定仍需确认。

确认记录包含：画像来源、模板候选与最终选择、既有画像处理、批准字段或推荐值修改、明确不适用项、规则与前端约定接入范围、三个工具 Skill 和 project-workflow 的接入范围、是否保留 .codex 本地资源、是否接入项目总门禁，以及每个写入阶段对应的 planId。模板选择即使已有用户预声明也要在首次初始化提示并记录确认；迁移或覆盖冲突必须使用新的 plan/apply 确认记录。

用户可确认全部已展示的推荐值，也可只确认部分。写入前回读相关文件，若期间发生变化，基于最新内容重新比较。只写仓库证据或用户决定支持的值；未确认内容按 [字段状态](profile-schema.md) 留在草稿。

用户只要求规则接入时，不额外安装插件、连接账号或开发业务功能；用户已要求搭建前端时，继续当前仓库的工程创建与业务实现，不重复索取同一授权。确认记录属于当前项目交付证据；不把业务值写回 resources 中的通用模板。
