# 来源路由

本文件负责选择需要读取的场景流程。任务规模、确认策略、文档产物和实施边界统一使用 [共用执行契约](common-workflow.md)，交付使用 [验收矩阵](acceptance-matrix.md)。

## 1. 先判断目标，再分类材料

先识别任务是新页面、增量修改、缺陷修复还是重构，再检查材料实际内容。不能仅因用户提供了文字就启动从需求到设计的完整流程，也不能仅因文件扩展名为HTML就认定它是业务代码。

| 来源及任务意图 | 读取流程 | 来源负责什么 | 不应据此推断 |
| --- | --- | --- | --- |
| Figma链接、frame或node，要求实现代码 | [Figma](figma-workflow.md) | 节点、组件、变量、布局和设计状态 | 服务端权限与业务契约 |
| 截图、选定视觉稿，要求忠实实现 | [截图](screenshot-workflow.md) | 可见区域的布局、视觉层级与样式 | 截图外行为、准确CSS视口或隐藏状态 |
| 线框原型、交互演示、原型工具导出HTML | [原型](prototype-workflow.md) | 信息结构、跳转、状态转换、交互意图 | 最终视觉或真实数据操作 |
| 既有业务HTML/CSS/JS，要求改造或迁入框架 | [HTML](html-workflow.md) | DOM、样式、事件、路由、资产和既有行为 | 需要重新设计或改写整个网站 |
| OpenAPI、接口块、请求样本、现有请求逻辑变更 | [API](api-workflow.md) | 请求、响应、字段、错误与数据生命周期 | 需要新增整套请求基础设施 |
| 尚无定稿设计的开放需求、新用户流程 | [需求](requirement-workflow.md) | 用户目标、范围、业务规则与完成条件 | 已经批准了某个新视觉方向或后端契约 |

现有页面的小修复先按共用契约定位问题。只有修复涉及对应来源时才增加场景流程，例如筛选条件导致错误页码时读取API相关步骤；按钮文案修正无需加载Figma或需求设计流程。

## 2. 单来源与组合执行

读取顺序：目标规则与共用契约、匹配的主场景、必要的补充场景、适用验收。每份流程在当前任务中只加载一次，已由 project-workflow 路由进入时不递归重启。

| 组合 | 分工和执行顺序 | 统一产物 |
| --- | --- | --- |
| 截图 + API | 截图解析页面区域，API映射数据和状态，汇合后实现 | 一份设计解析及对应字段映射，联合验收 |
| Figma + API | 读取指定节点与状态，再匹配接口；设计缺失的数据状态按项目规则处理 | 节点/组件映射、DTO/VO/UI对照、差异记录 |
| 原型 + 截图 | 原型负责流程，已确认截图负责视觉；同一状态绑定两种来源 | 状态转换表和视觉区域映射 |
| 原型导出HTML + API | 采用原型流程理解演示，API流程定义实际提交 | 导航/状态模型与真实请求计划；不另跑业务HTML迁移流程 |
| 业务HTML + 截图 | HTML负责保留行为，指定截图约束变更后的视觉 | 改造影响表及目标视觉对比 |
| 需求 + API | 需求限定用户目标，API限定可用字段和动作 | 范围/验收清单与接口差异 |
| Figma + 截图 | 明确两者版本、目标区域和状态；仅加载各自实际参与的部分 | 标明采用来源的区域表，冲突单独处理 |

原型工具生成的大量定位元素仍属于原型材料。只有用户要求保留或迁移其运行代码时，才额外使用HTML流程分析代码依赖。

## 3. 材料缺失、冲突和版本变化

为参与任务的材料记录：实际路径/URL、版本或读取时间、覆盖区域、状态、视口及可访问性。来源有更新时只重做受影响的分析和验证。

- Figma无法访问但有导出截图：可按截图流程继续已授权的可见部分，注明节点/变量未读取；用户要求节点级还原时，相关完成条件仍未满足。
- 只有桌面设计：先调查已有响应式约定；缺失的关键移动布局提出具体决定，普通换行和溢出修复按现有模式处理。
- 没有接口契约：只有任务涉及数据接入时才输出接口缺口或草案；用户已授权本地交互原型时可使用明确的模拟数据，真实联调保持未验证。
- 只有错误描述和源码：先复现并读取实际实现，不将其当作无设计稿新页面。
- 同一区域多个视觉版本：优先用户明确指定的版本，不能仅按Figma、截图等格式排序。
- 视觉要求与接口权限冲突：保留可信权限边界，列出视觉调整或契约确认的具体选项，不自行伪造字段或绕过鉴权。

只就会影响后续结果的缺失决定提问；确认点统一按共用契约执行。没有影响任务的歧义时继续实施。

## 4. 路由边界

专项能力从 [项目任务路由](../../project-workflow/references/task-routing.md) 选择。来源reference提供步骤，不替代Figma等工具调用的必需Skill前置要求。

路由中的设计探索适用于确实需要确定新视觉方向的任务；仅缺少页面稿但已有适用设计系统时，沿用现有系统，按需求流程补齐结构与状态。Figma路由的design context读取以工具和节点可访问为前提；无法读取时按本文件的截图降级规则处理，仍须保留节点相关未完成项。

用户要求创建/修改Figma文件时，使用项目中的设计写入路由；本组Figma流程负责设计转代码。用户只要求审计或给方案时，交付相应审查/方案，不自动进入业务实现。规则初始化和能力安装分别交给bootstrap与capability setup，不混入页面开发。
