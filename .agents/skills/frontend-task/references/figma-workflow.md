# Figma设计转代码

适用：从用户指定的Figma文件、frame或node实现本地页面与组件。创建文件、回写设计、组件库或动效编辑属于项目中的对应Figma工作流，不因读取设计而自动执行。共用边界见 [执行契约](common-workflow.md)。

先读取 [项目画像](../../../../docs/PROJECT_PROFILE.md) 的框架、主题、字体、图标与目录约定，以及 [组件目录](../../../../docs/rules/AI_COMPONENT_CATALOG.md)。Figma提供设计事实，目标项目决定工程实现。

## 1. 定位设计与读取能力

| 输入 | 核实内容 |
| --- | --- |
| 文件链接与node/frame | 文件标识、节点、页面名称、读取版本或时间；是否只实现其中一部分 |
| 页面与状态 | 目标路由、桌面/移动节点、弹层、变体、权限或错误状态 |
| 设计系统 | 相关组件库、变量模式、字体与图标资源、已有代码映射 |
| 接口和业务 | 实际契约来源、交互说明、角色及已确认的保留行为 |
| 验收条件 | 来源frame尺寸、目标浏览器/视口/DPR及允许差异 |

调用design context前分路径：装有 `figma@openai-api-curated` 插件的宿主先加载其 `figma:figma-design-to-code` 子技能，遵循其读取顺序、截图与资产要求；无插件宿主（含 Claude Code）按下节「MCP 直连用法」顺序执行。工具输入以当前宿主实际API为准，不猜测参数或节点内容。

先检查连接和节点可访问性。授权已覆盖设计读取时不重复询问读取许可。节点缺失、权限不足或工具未提供时，报告具体受限范围；已有导出图可作为 [截图流程](screenshot-workflow.md) 的降级材料，但不宣称已获得节点/变量信息。

### MCP 直连用法（无插件宿主路径）

无 Figma 插件时通过 Figma 官方 MCP server（Dev Mode 本地端点或远程服务）直连，Claude Code 宿主这是唯一路径。配置要点：在 Figma 桌面端开启 Dev Mode MCP server 或使用远程端点，把该 server 加入宿主 MCP 配置；工具名以宿主实际暴露为准，本节按能力描述引用。

按以下顺序读取，逐步降级：

1. **design context 优先**：对目标节点请求 design context（含变量、样式、资产引用与代码语义）。返回截断时按 frame/区域拆分重读，不把截断结果当完整页面。
2. **结构回退**：design context 不可用或权限不足时，用节点元数据（名称、类型、层级、尺寸、auto-layout 属性）建立结构事实。
3. **视觉回退**：配合节点截图取得像素事实，用于间距、层级与状态核对；截图不能反推变量名或组件语义。
4. **资产落地**：工具返回的资产地址多为本地临时源，仅限开发期预览；入库前下载为项目资产并核对格式。缺资产记录原因，不因此新增图标包或字体包。
5. **禁占位**：字段、文案、颜色缺失时记「未验证」，不用占位数据或猜测值冒充设计事实。
6. **对稿验收**：在与来源 frame 匹配的视口与状态下 1:1 对比实现，差异按布局→组件→细节顺序记录；节点级映射结论与截图证据分开登记。

## 2. 读取节点上下文与关联状态

1. 先读取指定节点及必要父级，确定frame边界、页面壳层和目标区域；不无差别遍历整个文件。
2. 获取设计上下文与实际预览，交叉核对组件树、可见内容和布局。返回内容被截断时按区域拆分读取，不能把截断结果当作完整页面。
3. 识别auto-layout方向、gap、padding、hug/fill/fixed、constraints、最小/最大尺寸和裁剪；映射到内容响应式行为，不能直接复制画布坐标。
4. 读取组件实例、属性、variants、交互状态以及实际关联的变量/样式；区分组件默认值与实例覆盖值。
5. 检查字体、文本样式、图标、图片、蒙版和效果。读取该任务涉及的变量模式或移动节点，记录未提供的状态。
6. 若工具返回动效数据或要求读取motion context，使用当前对应的motion Skill；静态节点不自动生成新动画。

Figma画布单位和frame尺寸不能直接推断为浏览器截图像素及DPR。视觉验收需明确渲染条件，长frame还应区分页面内容长度与浏览器高度。

## 3. 设计到工程的映射

在目标设计文档记录实际节点、来源时间、读取范围和以下映射。已有Code Connect或项目组件映射可优先参考，但仍需核对组件接口和实际行为是否符合当前任务。

| Figma节点/属性 | 设计值或语义 | 项目落点 | 处理与验证 |
| --- | --- | --- | --- |
| 布局容器 | auto-layout及尺寸策略 | 壳层/Grid/Flex/滚动容器 | 内容变化与窄屏布局 |
| 组件实例 | variant、状态、实例覆盖 | 现有组件及props/slot | 默认、禁用、选中等对应状态 |
| 变量/样式 | 颜色、间距、字体、主题模式 | 项目语义Token | 主题同步与变量冲突 |
| 图标/图片 | 资源、比例、裁剪和显示位置 | 项目资产或批准的图标封装 | 实际加载和清晰度 |
| 文案/字段 | 文本与展示格式 | i18n、VO及格式化函数 | 长文案、空值和数据状态 |

只在现有组件缺少所需且可复用的能力时扩展；一次性布局留在页面。生成的Tailwind、CSS-in-JS或其他框架示例需要转换为项目已确认实现，不引入第二套样式或请求设施。

资源优先使用工具返回的可用资产和项目资源，核对文件格式、加载方式及可持续访问性。临时下载地址不能未经确认成为生产依赖；缺失资产记录原因，核心资源缺失时保留视觉未完成项。

## 4. 补齐交互和数据决定

Figma可见状态不等于业务状态机。确定按钮动作、表单校验、弹层关闭、导航返回和加载/空/失败/权限的依据；未提供的状态优先沿用项目已有模式。

有接口时按 [API流程](api-workflow.md) 建立DTO/VO/UI映射，核对设计中存在但接口未提供的字段、枚举、格式和操作权限。不要以设计图中出现“删除”按钮为依据实现未授权服务端动作。

无法兼容的组件/Token、核心资产替换、未定移动布局、业务与权限冲突，先输出具体差异与推荐处理。已确认frame和可逆实现选择按共用契约推进；用户要求分阶段确认时才在指定阶段交付并等待。

依赖节点信息的范围进入编码前：目标节点及相关状态已识别，主要组件与资产有落点，适用接口有依据，影响结果的未决项已解决。连接不可用时，已授权的截图可见区域按截图流程进入编码，独立接口工作也可继续；节点/变量映射仍保留未完成。版本更新后只重读受影响节点，避免沿用过期映射。

## 5. 实施与视觉回归

1. 按主要区域实现壳层、内容、重复组件和弹层，逐区核对节点映射；使用已有组件接口表达变体。
2. 实现真实交互和适用数据状态，同步主题、i18n、图标及无障碍语义。装饰性节点不应成为无语义的交互控件。
3. 运行项目相关测试、静态/类型检查和构建，再按 [验收矩阵](acceptance-matrix.md) 实际打开目标路由。
4. 在与设计匹配的视口和状态下截图，对比结构、排版、资源、颜色和状态；按布局到细节顺序修正。
5. 对其他支持端验证内容重排、操作可达、弹层和长文本；在来源未提供的状态上记录派生依据，不伪称这些状态来自Figma。

## 6. 交付证据

按照 [验收记录](../../../../docs/rules/AI_ACCEPTANCE_EVIDENCE.md) 提供文件/node/frame、读取时间、实现区域、复用/扩展组件、资产落点、实际检查及未验证项。对比默认存 `docs/design/compare/<页面>/`，按目标约定调整。

来源截图、代码渲染截图和差异说明应能对应同一状态。节点不可访问、资产缺失、真实接口未联调及未覆盖的设计变体分别记录；不能用静态截图或构建成功代替真实交互验收。
