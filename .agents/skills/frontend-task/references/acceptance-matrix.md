# 验收矩阵

本文件把“完成”转换成可执行检查。范围依据 [共用契约](common-workflow.md)、[项目画像](../../../../docs/PROJECT_PROFILE.md) 的UI/接口矩阵和 [组件目录](../../../../docs/rules/AI_COMPONENT_CATALOG.md)，证据写入 [验收记录](../../../../docs/rules/AI_ACCEPTANCE_EVIDENCE.md)。

## 1. 确定本次必验范围

新页面验证主流程及其适用状态；增量任务验证变化区域与受影响调用方；缺陷修复先重放原复现，再验证邻近正常路径。无需对小修改穷举所有设备、语言和状态组合，但项目明确要求的检查不能省略。

开始前列出路由、角色、来源版本、浏览器、CSS视口、DPR、主题/语言、数据环境以及操作预期。按“通过、失败、未验证、不适用”逐项记录；不适用需要项目依据，缺少环境属于未验证。按 `deliveryTargets` 与页面声明同步产出本页生效标签集（查 [WebView 移动端规则](../../../../docs/rules/AI_WEBVIEW_MOBILE.md) 的激活条件表），逐页落纸后再选验收行。

| 层级 | 检查内容 | 通过依据 |
| --- | --- | --- |
| 自动化 | 相关单元/集成测试、静态/类型检查、构建、项目总门禁 | 实际命令、工作目录、退出码 |
| 视觉 | 布局、字体、Token、图标/素材、各状态、来源视口对比 | 渲染截图、来源与逐区域差异 |
| 交互 | 用户目标、导航、返回、表单、筛选、分页、弹层 | 实际动作、预期和实际结果 |
| 响应式 | 桌面/平板/移动支持范围、断点临界宽度、触摸和滚动 | 对应视口的动作与截图 |
| 无障碍 | 键盘、焦点、语义、可访问名称、对比度 | 实际操作和适用的自动检查 |
| 接口 | 真实非生产主流程、失败、权限、刷新持久化 | 脱敏网络证据及UI结果 |
| 运行状态 | 控制台、资源请求、应用启动和目标路由 | 新增错误清单、资源加载和可访问入口 |

## 2. 建立稳定的浏览器基线

1. 按实际命令启动或复用目标应用，确认打开正确服务、路由和本次构建；端口冲突不终止其他服务。
2. 先记录原有控制台/网络错误，验证后区分新增错误与已有问题，不能笼统声称“无错误”。
3. 设置CSS视口、DPR、主题、语言和测试角色；视觉比对时记录浏览器与缩放。参考图的截图像素不直接当作CSS尺寸。
4. 等待页面的实际就绪信号、字体、图片和数据状态，不只固定延迟；持续轮询页面不必等待永远不会出现的网络空闲。
5. 视觉基线尽量使用固定的脱敏数据，时间、随机值和动画的处理方式须记录。不能遮罩本次变更区域来规避差异。
6. 从真实控件完成主流程，同时观察请求与控制台；结束时记录结果和截图位置。

工具使用Browser/Playwright或画像登记的等价能力。手工操作可以形成真实证据，但必须标明手工；不能写成运行过自动化。使用 playwright-cli 时：在**业务项目根**目录运行（快照落在 cwd，避免污染其他仓库）；同机多任务/多项目并发时用**命名会话** `-s=<task-id>` 隔离浏览器实例（默认 `default` 会话会被并发方抢占）；工具不支持 DPR 与真机触屏模拟，超出能力的项（如 @2x、真机 tap、读屏播报）如实记入未验证项，不得宣称已验证。

## 3. 页面状态及触发方式

只验证页面真实存在的状态；静态展示页不必凭空增加请求和权限界面。数据页面至少覆盖项目要求的loading、empty、error和unauthorized。涉及交互组件时，同时核对交互态：hover（限指针设备）、focus-visible、pressed（:active）、selected（Tab/导航/行选中）。

| 状态 | 如何触发 | 必须核对 |
| --- | --- | --- |
| loading | 在测试环境延迟实际请求或使用明确的测试拦截 | 加载反馈、布局稳定、重复动作限制 |
| empty | 查询返回合法空集合，或筛选无匹配 | 首次无数据与筛选无结果语义正确，恢复入口可用 |
| error | 非生产失败响应、断网、超时或契约允许的业务错误 | 无伪成功、反馈可理解、输入与已有数据按约定保留 |
| unauthorized | 受控401/403或无权限测试角色 | 登录/无权限处理正确，敏感数据不残留 |
| disabled | 不满足校验/权限条件或正在提交 | 鼠标和键盘均不能误触发，禁用条件正确 |
| success | 实际完成读取或提交 | 反馈与结果一致，列表/详情缓存正确更新 |
| retry | 对失败场景执行允许的重试 | 不重复写入，失败仍可见，仅对安全操作重试 |

用拦截响应构造的状态记为模拟验证，不能标为真实服务联调通过。生产环境不执行故障注入或测试数据写入。

## 4. 视口、主题、语言与极端内容

- 根据画像选择桌面、平板、移动代表尺寸；每个受影响断点附近检查两侧布局。视口抽样不代表完整支持范围，不支持端需核对明确降级行为。
- 检查宽度和高度：弹层短屏可滚动、固定工具栏不挡操作、触屏无只能hover访问的功能；横竖屏只在支持范围要求时增加。
- 表格核对横向滚动容器、固定列和操作可达性；页面不应因长字段出现意外横向溢出。
- 使用长标题、长英文、无空格字符串、大数值、零值、缺失可选字段和大量数据检查换行、格式化与空值语义。大量数据场景依据实际分页/虚拟化方案。
- 只测项目支持的主题和语言。检查弹层、图标、错误态、禁用态与组件库主题同步；有持久化要求时刷新及重新进入核对。
- 若有设计源，先在来源视口比对，再检查响应式；其他视口合理适配不等于擅自改变来源视口设计。

## 5. 交互、无障碍及接口

| 场景 | 实际检查 |
| --- | --- |
| 导航 | 列表到详情、面包屑、浏览器前进后退、直接打开深链及刷新 |
| 筛选和分页 | 变更筛选后的页码/游标、排序、清空、快速连续操作、返回后的状态 |
| 表单 | 必填与跨字段校验、错误定位、重复提交、取消、失败重试和输入保留 |
| 弹层 | 打开时焦点、键盘访问、适用的Escape关闭、关闭后焦点返回、滚动锁释放 |
| 可访问性 | 原生语义、Tab顺序、焦点可见、图标按钮名称、标签/错误关联、对比度及减少动态效果 |
| 数据一致性 | 慢旧请求不覆盖新条件，操作成功后列表/详情刷新，失败无伪持久化 |
| 真实接口 | 在非生产环境核对方法、参数、认证、返回数据及用户可见结果；HTTP 200还需检查业务语义 |

自动无障碍工具不能替代键盘操作。接口详细边界参照 [API流程](api-workflow.md)，包括安全重试、权限和缓存；高风险最终动作仅执行已授权范围。

## 6. 失败处理与证据交付

每个失败记录触发条件、预期、实际、来源或代码定位、影响及后续动作。修复后重放失败用例和受影响回归，不能通过删测试、隐藏控件或改变测试数据规避问题。

证据至少包含：任务/来源版本、实际路由、检查环境、命令及退出码、操作步骤、截图或脱敏请求记录、偏差和未验证项。文件命名能区分路由、视口、主题和状态，不覆盖仍需对照的基线。

仅当本次必需检查均有通过证据，或用户明确调整了完成范围后，才报告相应范围完成。没有Browser、接口或账号时交付已验证部分及继续条件；截图、构建、Mock、HTTP 200都不能单独证明业务流程成功。
