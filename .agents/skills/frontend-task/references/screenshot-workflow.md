# 截图一比一还原

适用：从截图、选定视觉稿实现页面，或按参考图调整已有区域。只有线框结构时使用 [原型流程](prototype-workflow.md)；Figma节点可读时按 [来源路由](source-routing.md) 判断是否组合。任务规模、产物路径和确认规则遵循 [共用契约](common-workflow.md)。

本流程即视觉复刻主路径，全宿主可用：代理视觉读图 + 像素测量。宿主具备 OpenAI 运行时（Codex + 官方插件）时可叠用内置 `$product-design`（子技能 image-to-code）加速，其宿主能力边界见该技能顶层 SKILL.md。项目工程事实仍来自 [画像](../../../../docs/PROJECT_PROFILE.md)、[前端约定](../../../../docs/rules/FRONTEND_CONVENTIONS.md) 和 [组件目录](../../../../docs/rules/AI_COMPONENT_CATALOG.md)。忠实还原任务不启动无关设计探索。

## 1. 核实图片与目标范围

| 输入 | 需要检查 | 缺失时处理 |
| --- | --- | --- |
| 页面/区域、目标路由 | 全页实现还是只改某一块，哪些原行为保留 | 先查现有路由和当前请求 |
| 图片路径与版本 | 实际打开全部相关图片，记录默认、弹层、错误等状态 | 不用文件名或文字描述代替看图 |
| 截图条件 | 图片像素、CSS视口、DPR、浏览器缩放、裁剪、是否长截图 | 标记未知；不能直接把图片宽度当CSS宽度 |
| 素材与字体 | 原图、图标入口、字体文件、授权可用来源 | 查项目资源；影响还原的缺失资产单列 |
| 支持端、主题和语言 | 参考图覆盖哪些组合，其他组合采用何种项目规则 | 沿用已确认画像，不凭一张图增减支持范围 |
| 数据与交互 | 有无API文档、业务状态、弹层操作说明 | API适用时加载对应流程 |

仅在确定图片未被缩放或裁剪、采集方式明确时，才结合DPR换算CSS尺寸。长截图高度通常是内容长度，不能当作浏览器视口高度。缺少条件时可以先实现不依赖该条件的区域，但视觉精度结论需说明限制。

## 2. 设计解析与复用映射

从全局结构到局部细节分析，在目标设计文档记录以下适用内容；增量任务只更新变化区域。

1. 划分全局壳层、导航、内容区、工具栏、表单/表格、反馈和弹层，确认内容宽度、对齐线、滚动容器及固定/吸附关系。不要为单页重复创建已有壳层。
2. 提取Token：宽高约束、栅格、字体/字重/行高、颜色、间距、圆角、边框、阴影。每个值标记为可测、来源已知或估算，再映射项目现有语义变量。
3. 输出组件树：区域、职责、props/事件或slot、复用/扩展/业务域/页面私有、布局边界。Vue的emits、React回调按项目框架表达，不机械套用同一接口。
4. 建立状态矩阵：截图已展示的状态、项目必须支持但未展示的状态、派生依据。看不到hover、空态或移动布局不等于它们不存在。
5. 建立图标/图片与文案表：资产路径、显示尺寸、裁剪方式、替代文本、文案、i18n key及支持语言。识别不清的文字标注疑问，不能把OCR猜测写成业务事实。

| 区域/元素 | 来源状态 | 测量值或视觉要求 | 项目Token/组件 | 确定程度与待处理差异 |
| --- | --- | --- | --- | --- |
| 示例：筛选栏 | 桌面默认态 | 多列字段与右侧操作对齐 | 现有筛选表单及间距变量 | 窄屏重排沿用同类页面 |

沿用已确认视觉和项目组件，记录确实无法兼容的差异。需要新增Token或替换核心资产时先准备具体候选；只在会改变设计意图、支持范围或存在明确阶段验收要求时等待确认。普通CSS实现选择按现有模式推进。

## 3. 接口与页面结构

有数据接入或请求逻辑变化时执行 [API流程](api-workflow.md)，把可见字段映射到DTO、VO和展示格式；缺失、多余、类型不一致、枚举和权限字段单列。截图中的按钮只证明视觉存在，不证明用户有操作权限。

根据画像规划页面、组件、types/adapter/API入口、config/constants、语言包和必要Token的实际改动。无接口的静态页面不新增数据层。接口未提供但已授权模拟原型时，明确模拟范围及后续接入点。

编码前应已明确：区域结构、复用决策、主要资产、视觉依据、适用状态和字段来源。高影响歧义未解决时暂停其依赖部分；用户要求“设计解析后确认、结构后确认”时分别交付可审阅产物后等待。

## 4. 按布局、交互、数据逐步实现

1. 先复用壳层并建立主布局，再实现重复组件、表单和数据展示，最后处理细节；每完成一个主要区域就检查实际渲染。
2. 用Grid/Flex和内容约束表达布局。截图坐标用于分析，不将整个页面做成绝对定位画布；叠层或固定格式部件按实际需求定位。
3. 保留字体、行高、图片比例和长文本换行。不要为了接近截图把真实文字替换成图片，或裁掉内容来掩盖尺寸错误。
4. 按已确认Token、图标入口、主题和i18n实现。缺失素材使用项目允许的临时处理并登记，核心素材未补齐时不能宣称视觉完全还原。
5. 接上真实可操作控件及适用数据状态，验证禁用、反馈和导航；动态内容不应使按钮、表头和工具栏意外跳动。

新交互和修复按项目测试栈验证；纯视觉调整采用局部视觉与响应式检查。禁止自主美化、增加需求外模块或用不可访问的交互方式模拟视觉。

## 5. 对比、修正和交付

按 [验收矩阵](acceptance-matrix.md) 运行实际质量命令，再用Browser/Playwright在来源CSS视口、DPR、主题、语言和相同数据状态下截图。等待字体与主要资源完成，记录图片和渲染条件。

| 对比层级 | 优先检查 | 常见修正方向 |
| --- | --- | --- |
| 全局布局 | 壳层、内容宽度、纵向起点、列比例、滚动 | 容器和栅格约束 |
| 区域与组件 | 表单/表格尺寸、对齐、间距、弹层位置 | 组件参数和布局样式 |
| 字体与资产 | 字体加载、字重、行高、图标、图片比例 | 字体资源和资产映射 |
| 视觉细节 | 颜色、边框、阴影、状态与主题 | 语义Token及状态样式 |

并排图或叠图用于定位差异，像素差分需说明字体渲染、动画等环境因素。不能只凭一个相似度数字宣称合格，也不承诺不可验证的“误差为零”。先解决大布局偏差，再处理细节；修改后回归相关区域及支持端。

设计源视口之外，继续验证桌面、平板、移动、断点、适用主题/语言及加载/空/失败/权限状态。保存对比到目标约定目录，按 [验收记录](../../../../docs/rules/AI_ACCEPTANCE_EVIDENCE.md) 交付来源、实际条件、区域差异、已确认偏差和未验证项。Browser不可用时给逐区域自检，真实视觉和交互验收保持未验证。
