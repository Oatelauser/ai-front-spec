# 安装政策

1. 安装前重新读取状态：已安装且来源、名称和路径匹配则跳过。同名但来源无法确认时标记 source-unverified，不覆盖。
2. 插件只通过当前宿主支持的 Plugin Management 安装精确引用，不能用 npm、手工复制或相似 fork 替代；宿主没有该能力时报告阻塞。
3. 独立 Skill 使用能力清单固定仓库、实际目录和精确名称。`npx skills add <仓库> --skill <名称> -g -y` 或 skill-installer 都须匹配已批准来源；目录名不等于 Skill 元数据名称。
4. 遇到 Skill path not found，先用仓库 API 核对真实路径，再在同一批准来源内重试一次；仍失败记录未完成。不得转向未知仓库或覆盖同名 Skill。
5. Browser/Chrome/Computer Use 属于宿主能力，只检查；Figma/GitHub 连接使用宿主 OAuth/登录流程，仅在当前任务需要且已授权时连接，不索取或记录令牌。
6. 安装不授权外部创建、提交、发布、通知或生产写入，也不允许改变全局权限模式。项目 Skill 通过 bootstrap 接入，不使用全局安装器。
7. 不修改业务代码、测试、配置或规则。项目记录写入限于已授权的当前仓库 `docs/capability-state.json`；仅在 B/C 阶段按 [状态格式](status-model.md) 创建或更新，保留已有条目，不因仓库包含模板资源而拒绝记录。A 阶段只读，不写项目状态。

逐项报告精确命令或宿主操作、实际返回、安装路径、元数据/来源证据、连接状态和是否需要新会话。不能把安装成功写成当前会话可发现。
