# API接入与前端数据流程

适用：OpenAPI、接口文档、请求/响应样本、已有请求逻辑的接入或调整。纯视觉修改不新增数据层；单字段或请求缺陷按 [共用契约](common-workflow.md) 缩小范围，不重建模块。

先读取 [项目画像](../../../../docs/PROJECT_PROFILE.md) 的统一请求入口、Schema/生成目录、缓存、权限及接口验收约定，复用 [组件目录](../../../../docs/AI_COMPONENT_CATALOG.md) 中的表格、表单和状态组件。契约设计/审查使用适用的api-design；认证、输入、上传、敏感数据或新API涉及信任边界时使用security-review。

## 1. 读取契约与现有调用链

从页面控件追踪到hook/composable、业务API、adapter、统一请求客户端和测试。确认当前使用的查询库、认证注入、错误处理、取消及缓存机制，先找扩展点。

| 契约项 | 必须核实的适用内容 |
| --- | --- |
| 来源 | 文档/Schema位置、版本、环境、可信度及生成方式 |
| 请求 | method、path、path/query/body/header、必填、可选、类型和序列化 |
| 响应 | 包装层、成功语义、字段类型、可空性、缺省值和枚举 |
| 列表 | 页码起点或cursor、pageSize、total含义、排序、筛选及空结果 |
| 格式 | 日期/时区、金额/精度/单位、ID格式、文件或下载内容类型 |
| 会话与权限 | 凭据注入、角色/租户边界、401/403、退出登录后的数据清理 |
| 失败与并发 | 业务错误码、超时/取消、限流、版本冲突、幂等和重试约定 |

OpenAPI使用项目已有解析/生成工具或结构化读取，不用字符串截取猜字段。生成目录按已声明命令更新，不手改生成产物。文档与实际响应不一致时保留证据并提出契约问题，不能为了运行通过悄悄放宽关键校验。

无正式后端文档时只输出“草案，待后端确认”，注明推导来源。不能依据截图发明已存在的endpoint、认证方式或权限字段。没有接口环境可以先验证adapter和模拟状态，但真实接入不标为完成。

## 2. DTO、VO与UI逐字段映射

优先更新已有 `docs/api/<模块>.md` 或画像指定文档，引用权威Schema，避免维护一份很快失效的完整手抄副本。新增/变化字段、枚举、错误码及对应types位置必须可追溯。

| UI字段/动作 | DTO字段/类型 | VO字段/转换 | 格式与空值规则 | 权限/异常语义 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 示例：状态文本 | 契约中的状态码 | 已确认状态值 | 显示映射来自字典/i18n | 未知码按项目规则显示，不映射成成功 | 文档版本及字段 |

单列缺失、多余、类型不一致和权限相关字段。区分null、缺字段、空串、0和false；不能使用笼统的真值判断把有效零值替换成占位。时间、金额和大整数转换遵守契约，不丢精度或改变时区语义。

DTO保留外部契约，adapter处理结构转换，VO供页面消费，文案和显示格式按项目i18n/格式化入口处理。页面列、表单、筛选配置及字典复用现有config/constants边界，不到处比较后端魔法值。

## 3. 明确请求与状态变化

在编码前确定适用场景，普通行为沿用现有模式；未定义且会改变业务结果的语义先确认。

| 动作 | 请求与状态要求 | 回归重点 |
| --- | --- | --- |
| 首次加载 | 初始查询与项目默认条件一致 | 加载、成功、空列表和失败 |
| 筛选/搜索/排序 | 参数序列化正确；条件变化按契约重置页码或cursor | 新请求对应新条件，清空可恢复 |
| 快速连续输入 | 沿用防抖/取消机制；查询标识覆盖实际条件 | 慢旧请求不覆盖新结果 |
| 翻页/返回 | 保留应保留的条件，区分URL状态与组件临时状态 | 页码起点、边界、详情返回 |
| 提交修改 | 输入校验、提交中反馈、防重复；幂等/并发控制依据后端支持 | 成功更新、失败保留输入、冲突处理 |
| 操作后刷新 | 更新/失效相关缓存和详情，处理删除后空页 | 页面之间数据一致 |
| 退出或切换身份 | 使用现有会话机制清理/隔离权限相关缓存 | 旧身份数据不短暂泄漏 |

失败重试不一律打开。读请求也须遵守服务端限流和项目策略；写请求只有明确具备安全重试/幂等语义时才重试。提交超时可能意味着服务端已经成功，先按契约查询结果或提示状态不明，不能直接再次写入。

乐观更新仅在结果可预测且项目已有一致性策略时使用，明确回滚与并发处理。未知业务结果不能用本地成功反馈代替服务端确认。

## 4. 实现边界与确认点

进入数据接入前应明确：endpoint和字段来源、转换规则、请求入口、错误/权限处理、页面状态以及可执行的验证方法。权限、字段含义、幂等或并发契约存在冲突时，先给出差异和推荐处理；用户已确认的内容不重复询问。

1. 按画像在types、adapter、API入口和查询层落地变化；目录示例 `src/api/<模块>/{types,adapter,index}.ts` 只是候选，不替代已有工程结构。
2. 使用统一请求入口的Schema或等价运行时校验、错误归一化、超时/取消和认证机制。新增能力应放在合适层级，不在页面再次封装一套客户端。
3. 将请求结果连接到页面状态组件。区分后台刷新与首次加载，失败时已有数据是否保留依据项目约定；不能错误显示成“无数据”。
4. 接入适用的权限、禁用、提交成功/失败和安全重试反馈。客户端展示限制只提供体验，服务端鉴权仍是最终依据。
5. 模拟数据仅用于已授权的原型或测试，来源按项目开发环境约定明确标识；真实请求失败不静默返回Mock，也不在正式页面增加无关实现说明。

纯前端接入不擅自修改服务端契约。外部账号连接、真实通知或生产写入按已授权范围处理；本地测试和可逆实现继续推进。

## 5. 针对性测试与真实联调

测试围绕变化行为，复用已有测试栈。新增adapter覆盖真实样本、边界空值与未知枚举；查询逻辑覆盖参数、条件重置、竞态及缓存；提交覆盖失败、重复动作与适用冲突。不要仅断言函数调用次数而忽略最终状态。

| 场景 | 可使用的验证方式 | 必须观察的结果 |
| --- | --- | --- |
| 正常/合法空结果 | 契约fixture及非生产真实接口 | 参数、转换和UI一致 |
| Schema不匹配/业务错误 | 受控样本或测试响应 | 错误可识别，不吞异常、不显示伪成功 |
| 断网/超时/取消/500 | 测试环境或浏览器拦截 | 反馈、输入保留、取消与重试符合约定 |
| 401/403 | 非生产测试角色或明确模拟 | 登录/权限状态及敏感数据清理 |
| 竞态/并发冲突 | 控制返回顺序或版本冲突响应 | 新条件正确、冲突可恢复 |
| 刷新/重新进入 | 实际UI操作和再次读取 | 已要求持久化的数据真实存在 |

运行项目相关测试与质量命令，再按 [验收矩阵](acceptance-matrix.md) 从真实UI联调。记录方法、脱敏参数、状态、必要业务结果及页面行为，不保存令牌、密码或完整敏感响应。以模拟响应验证失败状态时单独标记，不混入真实联调结果。

通过 [验收记录](../../../../docs/AI_ACCEPTANCE_EVIDENCE.md) 交付契约来源、字段变化、实际路由/动作、请求结果、测试与未验证场景。HTTP 200不能单独证明成功，真实环境或数据缺失必须明确说明。
