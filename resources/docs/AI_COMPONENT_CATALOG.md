# UI 公共组件目录与 AI 选用规则

若项目没有 UI，可在 `ai-guidance.config.mjs` 中从必需文件移除本文件。

## 初始化入口与状态

使用 `$project-profile components` 初始化或更新本目录。命令先读取 `.codex/templates/component-catalog.template.md` 的结构和 `.codex/templates/component-catalog.presets.json` 的候选基线，再读取 `.codex/profile-state.json` 中由任一画像子命令写入且带有 `assessedAt` 和证据的 `maturity` 结果，以及 `docs/PROJECT_PROFILE.md` 的已确认字段；缺少成熟度结果时先执行共享成熟度扫描并持久化，不得因为组件命令先执行就替项目画像填写字段。`$project-profile` 裸命令只展示两个平级入口并推荐先运行 `profile`。

组件目录可以参考画像，但不替画像填写字段；画像也可以读取本目录中的真实组件证据，但不替本目录完成初始化。目录状态单独记录为 `componentCatalog.status`，规划候选与已实现组件必须明确区分。

对于空/萌芽项目，命令必须向用户展示并让用户选择组件基线：

- Vue：Element Plus 基线（推荐）
- React：Ant Design 基线（推荐）
- generic：框架中立基础组件契约（Shell、Button、Form、DataDisplay、Feedback、Icon）
- 自定义组件目录
- 暂缓

推荐项不是事实。用户选择后，仍须用 `$grill-me` 分轮处理本文件全部 `<待填写...>` 字段；每个字段必须填写事实、`无`、`不适用` 或记录 `deferred` 原因/影响/后续条件。无真实实现但已确认纳入未来规范的条目标记为 `planned`，不得写成已存在组件。

## 1. 选用顺序

AI 生成或修改页面时按以下顺序判断，命中后停止继续造组件：

1. 搜索公共组件目录和当前业务域组件。
2. 结构、交互和无障碍语义一致时直接复用。
3. 仅缺少通用变体时，先补测试，再扩展公共组件。
4. 含业务状态机、角色、权限或接口语义时，放入对应业务域。
5. 只出现一次且没有稳定接口的布局留在页面内部。

## 3. 跨组件规则

- 主题、颜色、间距和状态使用项目语义 token，不在页面写死视觉常量。
- 所有用户可见文案按项目国际化策略处理。
- 交互组件具备可访问名称、键盘操作、焦点可见和合理对比度。
- 交互组件须记录并覆盖交互态表现：hover（限指针设备）、focus-visible、pressed（:active）、selected（Tab/导航/行选中），落在决策边界或测试/示例列。
- 公共组件通过 props、children、slot 或等价机制接收内容，不直接请求业务接口。
- 组件目录记录职责和边界，不把具体页面决策误写成全局规范。

## 5. 新组件检查清单

- 是否已有组件覆盖至少 80% 的结构与交互？
- 是否能通过一个通用变体扩展，而不是复制实现？
- 是否不含角色、接口和状态机等业务耦合？
- 是否使用项目语义 token、资产、国际化和统一焦点样式？
- 是否先增加组件测试，并同步更新本目录和示例？
