# AI 兼容性矩阵

本矩阵列出「选了 A 就撞 B」的端兼容与选型冲突：按 confirmed 目标端集合与已答选型逐条查表，命中即提示，冲突级须裁决才放行落盘。消费方是 project-profile 技能（init/update 访谈）——不进 AGENTS.md 任务路由，任务期不需要它，改端走 update。本文件注册进 `requiredFiles` 进门禁（存在性 + 无占位符 + 链接合法）。不做校验脚本：扫描在 AI 访谈流程内执行，markdown 表足够，PE 校验管结构不管语义。

## 一、条目格式（8 列）

```markdown
| 级别 | 含 | 缺 | 特性 | 选型 | 冲突说明 | 裁决选项 | 详见 |
```

- **级别**：`冲突`（须裁决才放行落盘）/ `提醒`（须确认，可批量）——亮出而非禁令。
- **含**：四键名（browserWeb / mobileH5 / tabletWeb / webview）逗号列表——S 出现任意一个即真；`—` = 恒真。
- **缺**：四键名逗号列表——S 一个都不许出现才真；`—` = 恒真。
- **特性 / 选型**：技术特性域 × 具体选择——选型只准写 Q2–Q7 的字面答案或 `—`。
- **裁决选项**：给用户选的路，每条一句代价。
- **详见**：指向 `AI_WEBVIEW_MOBILE.md` 的域号 + 域名并列（如「域 7 WebView 能力与兼容」）——编号腐化肉眼可见；互链，单一知识两处消费不重复维护。

## 二、合同（命中判定，增补行照此）

合同三句话：

1. **含**：含 任一 ∈ S——含列所列键中任一键 ∈ confirmed 目标集合 S 即真；`—` = 恒真。
2. **缺**：缺 无一 ∈ S——缺列所列键无一出现在 S 才真；`—` = 恒真。
3. **选型**：选型列 = `—` 或 ∈ T——选型值是已答选型集合 T（Q2–Q7）的字面答案才真。

命中 = 含列任一 ∈ S ∧ 缺列无一 ∈ S ∧（选型列 `—` 或 ∈ T）。三半边全是查表（词 ∈ 四键枚举 / 答案 ∈ T），零语法零拼接零数数。

已知天花板：全-与条件、基数条件表达不了——真出现加前缀约定扩展（本句即预留位）；平台粒度（iOS/Android）低于端粒度，平台限定写进冲突说明列（如「仅 iOS 生效，Android 忽略」），不新开列。

## 三、扫描协议（AI 执行）

1. 取 confirmed 目标集合 S（user-confirmed 的 deliveryTargets 键）与已答选型集合 T（Q2–Q7）。
2. 逐条匹配合同三半边（命中公式见第二节）。
3. 消费时机三分：
   - **Q1 展示**：可扫子集 = 选型列为 `—` 的行（T 尚空，只有不依赖选型的行可判）；即时提示不落纸——其命中必被 materialize 前全量覆盖。
   - **materialize 前全量扫描**：落纸进 proposal 具名槽 `compatibilityScan: [{条目, 级别, 裁决, 时机}]`，时机 = `materialize`。
   - **update 复检**：落纸，时机 = `update`。

   **不落纸 = 未扫描。**
4. 冲突级未裁决 → 不得 materialize（挂既有分层审批闸门，零新机制）。

## 四、裁决记录去向

- materialize 时，裁决记录并入 PROJECT_PROFILE 第 10 节「维护信息」的兼容裁决记录（append-only）。
- update 复检先读该记录，跳过已裁未变条目。

## 五、现代容器项目的冲突出口

含 webview 的冲突行对全现代容器项目照样命中，**不存在无冲突豁免通道**。出口 = 裁决选项 ③ 收窄容器基线：容器名 + 最低版本落纸进 `deliveryTargets.webview.value`（如「企业微信 ≥4.x」），验收矩阵引用同一字符串且须含该基线真机——零新字段。
