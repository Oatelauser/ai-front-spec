# 既有HTML改造与框架迁移

适用：原始网页HTML/CSS/JS的局部修改、可运行页面改造或迁入当前项目框架。原型工具导出的演示页面优先使用 [原型流程](prototype-workflow.md)；新视觉参考按需增加 [截图流程](screenshot-workflow.md)。执行边界见 [共用契约](common-workflow.md)。

读取 [项目画像](../../../../docs/PROJECT_PROFILE.md) 的框架、路由、资产、样式和请求入口，以及 [组件目录](../../../../docs/AI_COMPONENT_CATALOG.md)。迁移的目标是保留要求中的可观察行为，不是将全部DOM逐行转换成组件。

## 1. 明确改造模式与运行基线

记录HTML入口、配套样式/脚本/资源目录、启动方式、目标路由、修改区域及保留功能。输入只有网页URL时，先确认能访问的内容及任务范围，不能把抓取到的HTML当作完整应用源码。

| 模式 | 优先动作 | 必须保持 |
| --- | --- | --- |
| 原页面局部修改 | 定位相关DOM、选择器、事件与调用者 | 未修改区域的布局、交互和运行方式 |
| 静态页面迁入框架 | 分离内容、重复结构和状态，映射现有壳层/组件 | 信息、链接、资产、表单语义和可访问性 |
| 带脚本页面迁入框架 | 先复现业务行为及副作用，再迁移状态和事件 | 筛选、排序、提交、导出、导航等已要求行为 |

能运行时在原实现实际操作一次，记录入口、关键动作、结果、控制台和资源问题。不能运行时记录依赖缺失和静态观察范围，不把未测试行为称作“已保留”。

## 2. 读取依赖与影响范围

1. 识别DOM语义、主要区域、表单控件、动态插入区、模板和重复项。记录id、data属性、锚点及脚本使用的选择器。
2. 检查CSS入口、全局reset、选择器优先级、主题变量、媒体查询、字体、伪元素和第三方样式；找出会影响其他路由的全局规则。
3. 追踪事件绑定、委托、内联处理、定时器、观察器、全局变量和直接DOM修改。确认绑定和清理时机，避免新旧两套事件同时执行。
4. 检查跳转、hash/history、查询参数、表单默认提交、浏览器返回以及深链刷新；区分普通链接、下载和站内路由。
5. 读取fetch/XHR、存储、认证、第三方SDK和导出/上传实现；业务请求变更按 [API流程](api-workflow.md) 处理。
6. 核对相对/绝对资源路径、CSS中的url、base路径、模块加载顺序和外部资源来源。迁入子路由或部署子目录时不能只验证首页资源成功。

| 原元素/行为 | 相关文件或选择器 | 保留/替换/移除 | 目标组件/模块 | 验证方式 |
| --- | --- | --- | --- | --- |
| 示例：筛选后导出 | 表单事件与导出函数 | 保留业务行为，迁移事件 | 现有筛选组件和业务导出入口 | 请求参数、文件内容/类型、失败反馈 |

新建或更新目标设计文档中的影响表；纯逻辑缺陷只记录相关行为，不强制生成整页Token和组件树。

## 3. 迁移计划与确认边界

优先复用既有组件和Token；沿用目标项目的CSS Modules、scoped或其他已确认机制。不要把原页面的全局样式直接注入所有路由，也不要为迁移新增第二套UI库。

| 原实现 | 目标处理原则 |
| --- | --- |
| 复制多份的DOM块 | 数据驱动重复结构，只有稳定复用时才提取公共组件 |
| 直接改DOM的业务逻辑 | 迁入框架状态和事件；第三方控件需要命令式操作时隔离到组件生命周期 |
| 页面全局变量 | 分清页面局部、URL、共享客户端和服务端状态，不全部升级成全局store |
| 定时器、订阅、监听 | 在组件卸载或依赖变化时清理，检查重复挂载 |
| HTML字符串插入 | 使用结构化渲染；必须展示外部富文本时沿用项目清洗和安全策略 |
| 相对资源与下载链接 | 按目标构建和部署base处理，验证嵌套路由 |

对明确要求保留的行为直接实施。若替换会改变URL、表单提交语义、文件输出、登录态或第三方依赖，先列具体前后差异，解决未决决定再执行。用户明确要求迁入React/Vue不代表授权重做视觉或删除未理解的脚本。

编码前至少明确：原行为基线、目标入口、样式边界、事件/状态归属、资产映射和回归方法。无法解释的关键行为先调查，不能用删除代码让页面“能打开”。

## 4. 分区域实施

1. 建立目标路由和壳层，先保证文档结构与主要资源正常渲染。
2. 按影响表逐区迁移布局和样式，保留语义标签、label关联、按钮类型、链接用途及焦点顺序。
3. 每迁移一个交互就移除已替代的旧绑定，验证一次完整动作；不能同时保留内联onclick和框架onClick导致重复请求。
4. 接入原有数据来源或已批准的新契约，保留查询条件、错误状态与权限处理。导出、下载和上传要检查实际结果，不只检查点击反馈。
5. 检查卸载重入、重复打开弹层、切换路由后的监听和滚动恢复；清理本次不再使用的资源前核对引用。

第三方库的升级、替换和外部素材引入按任务范围处理。涉及用户输入、富文本或上传等信任边界时使用适用的security-review；普通HTML改造不自动触发Figma或设计探索。

## 5. 回归与交付

先运行项目真实测试、静态/类型检查和构建，再按 [验收矩阵](acceptance-matrix.md) 重放原行为基线。

- 核对链接、锚点、站内跳转、浏览器前进后退及目标路由直接刷新。
- 核对筛选、排序、分页、清空、提交、取消、导出/上传和弹层的适用成功/失败路径。
- 核对资源请求、嵌套路由下的图片/字体/CSS、控制台新增错误及重复请求。
- 核对改动区域在支持视口的布局、键盘和焦点；全局样式变动时至少检查受影响邻近页面。
- 迁移前后对比视觉与操作结果，有意变化要对应用户要求；原实现已有缺陷与本次回归分开记录。

通过 [验收记录](../../../../docs/AI_ACCEPTANCE_EVIDENCE.md) 交付原入口与新路由、保留/变更行为、实际验证、资源或依赖限制及未验证项。无浏览器时提供静态影响分析，但不宣称运行行为已全部保留。
