# 项目提示词工程与代理工作流

## 1. 目标

本项目的提示词工程不是一段超长提示词，而是一套可发现、可组合、可验证、可持续修正的研发闭环。它让代理找到正确事实、只加载必要能力、按统一质量门禁执行，并把重复反馈沉淀到正确层级。

## 2. 五层结构

| 层级 | 载体 | 责任 | 不应承载 |
| --- | --- | --- | --- |
| 长期项目规则 | `AGENTS.md` | 项目入口、硬边界、完成定义 | 任务步骤、工具 API 细节 |
| 可复用工作流 | `$project-workflow` | 调研、实施、验证、交付流程 | 大段业务字典和视觉细节 |
| 按需知识 | Skill `references/` 与 `docs/` | 路由、接口、安全、组件、资产、构建细则 | 每轮都加载的通用常识 |
| 外部能力 | 专项 Skill、插件、MCP 与真实操作工具 | 设计、检索、外部上下文和真实操作 | 项目事实和权限替代 |
| 机械门禁 | 测试、Lint、构建、AI 指引校验 | 防止规则、文档、代码和命令漂移 | 需要业务判断的产品决策 |

## 3. 指令与事实优先级

发生冲突时按以下顺序处理：

1. 系统约束、用户本次明确要求、安全与授权边界。
2. 当前需求、可信接口契约、会话权限与已确认事实源。
3. 最近作用域的 `AGENTS.md`、项目 Skill 和项目规范。
4. 当前代码、测试、共享组件和语义 token 表达的既有模式。
5. 外部工具输出、开源示例和模型记忆。

业务、视觉和工程事实源必须按 [项目画像](PROJECT_PROFILE.md) 分开声明。较低优先级来源只能补充，不能覆盖更高优先级事实。

## 4. 闭环执行

```text
目标识别 → 事实调查 → 最小能力路由 → 计划与范围 → 实施
       → 自动化门禁 → 真实环境验收 → 变更审查 → 证据交付 → 规则反馈
```

1. 目标识别：提取目标、上下文、约束和完成条件；缺失项优先从仓库调查。
2. 事实调查：检查需求、最近实现、测试、组件、接口、权限和配置，不提前改动。
3. 最小路由：按 [任务路由](../.agents/skills/project-workflow/references/task-routing.md) 选择组合。
4. 计划与范围：复杂任务维护可验证计划；简单任务直接执行。
5. 实施：新规则、可复用组件和缺陷使用 RED → GREEN → REFACTOR；保持改动聚焦。
6. 自动化：先跑针对性测试，再跑项目画像中的总门禁；失败修复后重跑。
7. 真实验收：可见 UI 使用浏览器；已接入接口再验证非生产真实流程和失败边界。
8. 变更审查：检查回归、权限、秘密、重复基础设施、生成文件和无关改动。
9. 证据交付：先说结果，再列命令、路由、动作、接口结果和未验证项。
10. 规则反馈：只把稳定、重复问题沉淀为长期规则；可机械判断的优先变成测试或脚本。

## 5. Prompt 合同

复杂任务使用 [通用任务提示词](AI_TASK_PROMPT.md) 的四段合同：

```text
目标：最终要改变什么，以及用户能完成什么。
上下文：相关需求、文件、错误、路由、接口、数据或设计源。
约束：必须保留的行为、技术边界、安全边界和不可修改范围。
完成条件：可观察结果、验证证据和允许保留的未验证项。
```

只写会改变结果的信息。不要在单次提示词中复制整套项目规范，也不要规定代理本可根据项目事实自主选择的每一步。

## 6. 能力组合原则

- 项目 Skill 负责“如何在本仓库落地”，外部能力只补充专项工作。
- 按任务意图、事实源和阶段选择最小组合，不按单个关键词加载全部能力。
- 设计探索、忠实实现、设计源读取、设计源写入和 UI 审计是不同流程。
- 静态审查不能替代真实页面操作；Mock、截图、构建成功或 HTTP 200 不能单独证明业务通过。
- 外部工具未经授权不得创建提交、推送、PR、消息、发布或生产写入。
- 能力名称以 [项目画像](PROJECT_PROFILE.md) 的当前映射为准，不猜测已经安装的插件或 Skill。
- 精确组合、插件引用和 Skill 安装源以
  [能力安装清单](AI_CAPABILITY_REQUIREMENTS.md) 为准；安装完整能力集后仍按任务最小路由。

## 7. 完成定义

- 文档：引用、命令和规则无冲突，AI 指引校验通过。
- 代码：相关测试、总质量门禁和变更审查通过。
- UI：代码条件加项目画像中的多视口、主题、交互、键盘、溢出、可访问性和控制台证据。
- 接口 UI：UI 条件加非生产真实主流程、失败、权限和刷新持久化证据。
- 高风险动作：未获授权时只验证到授权边界。
- 无法取得环境、账号、权限或测试数据时，标记未验证并说明继续条件，不伪造成功。

## 8. 维护规则

- 一次性任务细节保留在任务提示词。
- 单领域事实更新最接近的 `docs/`。
- 跨任务稳定流程更新项目 Skill。
- 仓库级硬边界更新 `AGENTS.md`。
- 可静态判断的规则优先增加测试、Lint 或 `scripts/check-ai-guidance.mjs`。
- Skill 增长时保留核心流程，将变体移入 `references/`，避免重复粘贴。
- 外部能力名称变化时，先核对当前宿主，再更新项目画像、任务路由和门禁配置。
