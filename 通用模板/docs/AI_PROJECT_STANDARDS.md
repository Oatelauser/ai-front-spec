# AI 项目研发规范模板

具体项目值以 [项目画像](PROJECT_PROFILE.md) 为单一事实源。本文件定义跨项目稳定的边界。

## 1. AI 责任

- 明确 AI 可以提供的解析、生成、检索、建议、解释和编排能力。
- 对高风险领域声明 AI 不得替代的正式判断、审批、处置、复核或归档。
- AI 输出可被有权人员修改、采纳或拒绝；需要审计的系统记录输入版本、输出版本、状态和业务关联。
- 外部能力失败不得覆盖已经固化的业务事实。

## 2. 数据与安全

- 在系统边界对用户输入、文件、接口响应和外部工具输出执行 Schema 或等价校验。
- 身份、角色和权限来自可信会话、令牌或权限服务，不接受客户端自报身份。
- 前端或客户端权限只负责体验和提前拦截，服务端重复执行完整鉴权。
- 敏感字段默认最小可见；日志和交付报告不记录密钥、令牌和未脱敏数据。
- 地址、密钥和环境差异通过环境配置或秘密管理系统注入，禁止硬编码。
- 外部写入、删除、生产操作和通知发送必须满足授权、审计、幂等与可恢复要求。

## 3. 接口与数据契约

- 明确接口契约的单一事实源，以及生成代码和手写业务接口的目录边界。
- 所有请求经过项目画像声明的统一入口。
- 外部输入必须运行时校验；静态类型不能代替边界校验。
- 命令类接口使用幂等键、版本或等价并发控制，不能静默覆盖。
- 错误必须可识别、可追踪且不泄露敏感信息；只重试安全、幂等的失败动作。

## 4. 工程约束

- 复用项目画像声明的语言、框架、组件、样式、主题、国际化和状态管理设施。
- 共享组件不承载业务状态机、角色判断或接口调用。
- 状态更新保持不可变；稳定业务规则优先实现为纯函数并先写测试。
- 不手工修改生成目录，不引入与现有能力重叠的基础设施。
- 保持文件和函数聚焦，错误在合适层级处理并向用户提供可理解反馈。

## 5. 测试与质量

- 新规则、缺陷和可复用组件执行 RED → GREEN → REFACTOR。
- 先运行最窄的相关测试，再运行项目画像中的总质量门禁。
- UI 变更执行真实浏览器验收；接口 UI 使用非生产环境和安全测试数据完成真实流程。
- Mock、fixture、截图、构建成功或 HTTP 状态不能单独作为业务通过证据。
- 删除、批量变更、通知、发布和生产写入只验证到授权边界，除非获得明确授权。

## 6. AI 协作

- 修改前读取 `$project-workflow`，调查需求、实现、测试和任务相关文档。
- 项目内部事实优先于外部 Skill、插件、示例代码和模型记忆。
- 修改范围保持聚焦，尊重工作区已有改动，不执行破坏性操作。
- 无法验证时说明具体阻塞和继续条件，不添加静默回退或宣称完成。
- 持久决策写入最窄正确层；可机械判断的规则写入测试、Lint 或 AI 指引校验器。
