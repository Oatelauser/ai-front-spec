# 截图一比一还原

适用：从截图或选定视觉稿实现页面，或按参考图调整已有区域。它不是独立任务类型，而是 `new-page`、`incremental`、`bug-fix` 或 `refactor` 的 `visual` 来源/影响模式。任务规模、产物路径和确认规则遵循 [共用契约](common-workflow.md)。

## 1. 核实图片、状态与目标范围

开始前实际打开全部相关图片，不用文件名或文字描述代替看图，并记录：

| 证据 | 必须记录 |
| --- | --- |
| 图片 | 路径/URL、版本/日期、像素宽高、格式、是否裁剪或长截图 |
| 渲染条件 | CSS viewport、DPR、浏览器、缩放、主题、语言、页面状态 |
| 范围 | 全页/区域、目标路由、需保留的原行为、排除区域 |
| 支持端 | 来源覆盖、项目确认端、推导端、未验证端 |
| 资产 | 图片、图标、字体、授权、尺寸、比例、裁剪和替代方案 |

图片像素宽度不能直接当作 CSS viewport。长截图高度通常是内容长度，不能当浏览器视口高度。条件未知时可以实现不依赖该条件的部分，但视觉精度必须标记为 `unverified`。

## 2. 设计解析和资产清单

从全局到局部建立设计解析，增量任务只更新变化区域：

1. 划分壳层、导航、内容区、工具栏、表单/表格、反馈、弹层、固定/吸附区和滚动容器。
2. 提取宽高、栅格、字体/字重/行高、颜色、间距、圆角、边框和阴影；每个值标记可测、来源已知或估算。
3. 映射项目现有语义 token 和公共组件，不为单页重复创建壳层。
4. 建立组件树，记录复用、扩展、业务域或页面私有决策。
5. 建立截图已展示、项目必须支持但未展示、由项目规则推导的状态矩阵。
6. 建立资产清单：

| 资产类别 | 默认处理 |
| --- | --- |
| 项目已有资产 | 优先复用并记录路径 |
| 用户提供本地资产 | 保存到任务 `assets/`，记录来源 |
| 品牌、图标、字体 | 使用项目批准入口，记录授权和回退 |
| 截图中存在但无法取得 | 使用明确占位并标记未验证 |
| 外部/AI 生成资产 | 记录来源、授权和可交付状态 |
| Base64/临时 URL | 不直接写入生产代码 |

不要把截图作为背景图交付；截图中的文字、按钮、导航、表单和可交互控件必须实现为真实 DOM/UI。

## 3. 视觉实现和对比循环

```text
读取图片元信息
→ 确认来源视口/DPR和页面状态
→ 建立区域、Token、组件和资产清单
→ 实现结构与真实控件
→ 在相同视口/DPR生成截图
→ 按区域对比最大差异
→ 修复差异并重截图
→ 检查确认端和关键断点
```

使用 Grid/Flex 和内容约束表达布局，截图坐标只用于分析；不要把整个页面实现成绝对定位画布。叠层、固定和吸附元素按实际行为定位。

优先修复顺序：页面宽度/容器、布局骨架、字体与行高、间距、颜色和边框、图片裁剪、图标、细节阴影。每轮记录来源截图、实现截图、视口/DPR、变化区域和剩余差异。

## 4. 边界

截图只证明可见视觉和该截图对应状态，不自动证明：

- 截图外的交互、路由和业务行为；
- API、权限、数据字段或真实提交；
- 其他视口、主题、语言或短屏；
- hover、focus、loading、empty、error、disabled 等未展示状态。

这些内容按原型、HTML、API、需求和项目事实补齐，并在验收中单独记录。
