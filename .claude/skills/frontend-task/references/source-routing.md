# 来源路由

本文件负责选择需要读取的场景流程。任务类型固定为 `new-page`、`incremental`、`bug-fix`、`refactor`；来源和影响模式独立记录，避免为每种组合制造任务类型。

## 1. 先判断任务类型，再分类材料

| 判断 | taskType |
| --- | --- |
| 新增路由、页面或完整页面级体验 | `new-page` |
| 修改已有页面或组件，保留未涉及行为 | `incremental` |
| 有可复现错误现象，需要修复 | `bug-fix` |
| 内部结构变化且外部契约等价 | `refactor` |

若重构改变视觉、交互、路由、接口、权限或公共组件契约，停止按纯 `refactor` 执行，重新分类或进入高影响确认。

## 2. 来源路由

| 来源及意图 | 读取流程 | 来源负责什么 | 不应推断 |
| --- | --- | --- | --- |
| 截图/选定视觉稿，要求忠实实现 | [截图](screenshot-workflow.md) | 可见区域布局、视觉层级、样式和资产线索 | 截图外行为、准确 CSS 视口或隐藏状态 |
| 线框原型、交互演示、原型工具导出 HTML | [原型](prototype-workflow.md) | 信息结构、跳转、状态转换和交互意图 | 最终视觉或真实数据操作 |
| 既有业务 HTML/CSS/JS，要求改造或迁移 | [HTML](html-workflow.md) | DOM、样式、事件、路由、资产和既有行为 | 必须重写整个网站 |
| Figma frame/node，要求实现代码 | [Figma](figma-workflow.md) | 节点、组件、变量、布局和设计状态 | 服务端权限和业务契约 |
| OpenAPI、接口块、请求样本、请求逻辑变化 | [API](api-workflow.md) | 请求、响应、字段、错误、缓存和生命周期 | 需要新增整套请求基础设施 |
| 开放需求、新流程、尚无定稿视觉 | [需求](requirement-workflow.md) | 用户目标、范围、业务规则和完成条件 | 已批准视觉方向或后端契约 |

## 3. 影响模式

根据变化清单可多选：

- `visual`：布局、字体、token、资产或主题；
- `behavior`：导航、交互、表单和状态转换；
- `data`：请求、字段、缓存、权限和持久化；
- `structure`：组件边界、路由、构建入口和依赖；
- `compatibility`：响应式、浏览器、WebView、键盘、触摸、无障碍、安全区域或短屏。

## 4. 组合执行

| 组合 | 分工和顺序 |
| --- | --- |
| 截图 + API | 截图解析视觉；API映射字段和状态；联合验收 |
| 原型 + 截图 | 原型负责流程；截图负责同一状态的视觉 |
| Figma + API | Figma负责设计状态；API负责真实字段和权限 |
| HTML + 截图 | HTML负责保留行为；截图负责指定视觉变化 |
| 原型 + API | 原型负责演示流程；API负责真实提交语义 |
| 需求 + API | 需求限定目标；API限定字段和动作 |
| Figma + 截图 | 按版本、区域和状态绑定，冲突单独记录 |

每份场景流程只加载一次。原型工具生成的定位元素仍属于原型材料；只有用户要求迁移其运行代码时，才增加 HTML 依赖分析。

## 5. 缺失、冲突和版本

记录实际路径/URL、版本或读取时间、覆盖区域、状态、视口/DPR和可访问性。来源更新时只重做受影响分析和验收。

- Figma不可访问但有截图：可按截图流程完成可见部分，节点/变量保持未验证；
- 只有桌面设计：调查已有响应式约定，缺失的关键移动布局列为决定；
- 没有 API 契约：只有涉及数据时输出契约缺口，授权的本地原型必须标记 mock；
- 只有错误描述和源码：先复现，不把它当作无设计新页面；
- 同一区域多个版本：优先用户明确指定的最新版本，并记录来源绑定；
- 视觉与权限冲突：保留可信权限边界，列出具体确认项，不伪造字段或绕过鉴权。

无法由仓库、来源或规则消解的高影响冲突，进入 `plan` 决策前沿，不静默选择。

路由边界：

- 用户只要求审计或给方案时，交付相应审查或方案，不自动进入业务实现。
- 画像维护与能力安装分别交给 `$project-profile` 与 [能力安装清单](../../../../docs/capabilities.md)，不混入页面开发。
