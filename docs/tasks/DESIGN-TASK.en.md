# Design Task Guide ($design-task)

In one sentence: **you state the goal, it produces 2–3 direction drafts backed by a design system; you pick, refine over rounds, and freeze a hand-off-ready final.** It designs only — implementation belongs to `$frontend-task`.

## 1. How to enter (two ways)

- **Invoke directly** — say:

  ```text
  $design-task design a brand hero landing page for a mobile commerce app, restrained premium style
  ```

- **From a task flow**: when `$frontend-task` hits a new page with no visual reference, the agent asks "quick direction or professional design?" — choosing **professional design** enters this lane; **quick direction** goes to `$prototype` (a one-off direction check, not this lane).
- **Lightweight fully-automatic (auto mode)**: put `auto` in the first sentence — zero questions, zero confirmations (design system freezes directly, finalization follows the fallback chain automatically), output is marked as a *candidate final*; unattended agent runs use the same path. You review afterwards: one word of approval confirms it, or keep revising. While auto runs, anything you say mid-flight takes priority.

The rule of thumb: **high aesthetic bar, multiple refinement rounds, systematic brand feel → this lane; just want a rough direction fast → prototype.**

## 2. The five steps you will experience

| Step | What happens | What you do |
| --- | --- | --- |
| ① Brief | Agent asks for page goal, content inventory, brand constraints (or fill the [brief template](../../.agents/skills/design-task/templates/design-brief.md) once) | State goals and preferences |
| ② Design system first | Agent derives **selection rationale** via `$ui-ux-pro-max` (palette, font pairing, layout pattern, anti-patterns) | **Confirm or adjust** — once frozen (SYSTEM.md), every draft shares it |
| ③ Drafts | 2–3 direction variants (generated by Stitch; if unavailable the agent self-authors HTML and **tells you the fallback happened**) | Open the variant page in a browser and browse |
| ④ Pick & refine | After you choose, the agent makes scoped edits and verifies each by reading back, then shows before/after | Say "pick X + change Y"; repeat as needed |
| ⑤ Freeze | Five artifacts archived to `docs/design/<feature>/v1/` with hand-off notes | **Frozen only on your nod** — artifacts and the chosen draft are shown for confirmation; not happy? keep revising, **as many rounds as it takes**; after confirming, implement anytime via `$frontend-task` (starting development before confirmation is also allowed — the chain is marked "unconfirmed final") |

## 3. A dialogue example (copy and adapt)

```text
You:  $design-task design a login page for a B2B SaaS, deep-blue brand, professional feel

Agent: Selection rationale (from local design-data retrieval) —
       palette #1E3A8A deep blue + Inter, copy-left/form-right layout.
       Confirm this system or adjust?

You:  Switch the font to a geometric sans

Agent: SYSTEM.md v1 frozen ✓. Generating 3 direction variants (~2 min)…
       Ready — open docs/design/login/prototypes.html and browse (?variant=a/b/c)

You:  Pick A; loosen the form spacing; move error hints below the inputs

Agent: Edited, read-back verified ✓, before/after screenshots at …
You:  This is the one
Agent: v1 finalized and archived ✓ (code.html / DESIGN.md / screen.png / PROMPTS.md / CONTRACT.md)
       Implement anytime: $frontend-task --source=html docs/design/login/v1/
```

**How to phrase refinement requests** (this matters a lot):

- ✅ Good = **location + what changes + what stays**: "Only the Hero primary button: switch to brand color; keep size, copy, and navigation untouched"
- ❌ Bad = vague adjectives: "make it feel more premium"

## 4. After the final version

| You want | Go to | Notes |
| --- | --- | --- |
| Implement the page | `$frontend-task` | The frozen design becomes the visual baseline (one of the four source kinds) |
| Small tweaks (swap an icon, copy change, a single value) | Just tell `$frontend-task` | Does not reopen this lane; the agent logs it to DRIFT for reference |
| Big changes (palette / layout system / cross-page direction) | Back to `$design-task` | Produces v2 automatically and reconciles drift since the last version |

## 5. When NOT to use it

| Scenario | Use instead |
| --- | --- |
| Quick direction check, interaction or state experiment | `$prototype` |
| Spacing, alignment, or fidelity issues on an implemented page | `$frontend-task` direct fix |
| Batch image compression, guideline audit, E2E | `$tinypng-compress` / `$web-design-guidelines` / `$webapp-testing` |

## 6. Agent-internal rules at a glance (nothing for you to manage; match symptoms here)

- **Edit read-back gate**: after every edit the agent re-reads HTML/screenshot/metadata — Stitch occasionally returns success without persisting; this gate catches the fake.
- **Iteration re-verification gate**: self-authored drafts keep a "fixed issues" list, re-checked at the end of every round so fixes never regress; before delivery the full page goes through a browser pass (multi-viewport / overflow / control styling) plus one impeccable detect run — acceptance stays light, never the full heavy suite.
- **Finalization fallback chain (rigid)**: ⓪ auto-retry download (fully automatic on hit) → ① **manual export** (when explicitly asked, click "Export → zip" on the Stitch website, three seconds) → ② hi-res screenshot restoration (screenshots are a first-class source, not a downgrade) → ③ agent-authored final — each failing tier drops to the next automatically with a clear announcement; never stalls, never switches paths silently.
- **Candidate finals**: auto output or finals developed before confirmation are marked "unconfirmed" (PROMPTS.md records source and confirmation status); your one-word nod later confirms it, or revisions route per section 4.
- **Artifact discipline**: iteration workspace `.stitch/` (not committed); finals in `docs/design/<feature>/vN/` as five artifacts, **versions only increment, never overwrite**; `CONTRACT.md` marks everything the prototype did not say as to-be-confirmed — business rules are never invented from screenshots.
- **Fallback**: Stitch unavailable → agent self-authors HTML variants inheriting the same SYSTEM.md (no style break), and clearly announces the downgrade — never silent.
