# Skill, Plugin, and CI Upgrades

## 1. Version facts

- Starter version: 根目录 manifest 的版本字段.
- Vendored upstream commit: 根目录 manifest 的 vendored 提交字段.
- npm package versions: 根目录 manifest 的 packages 字段.
- Editable Skill source: `.agents/skills/`.
- Claude mirror: `.claude/skills/`, generated by script.

## 2. Check and review

```bash
node scripts/update-vendored.mjs check
node scripts/update-vendored.mjs --diff <skill-name>
```

Review upstream added/removed/changed files and repository reference impact before upgrading. Entries without a repository only report their source.

## 3. Online upgrade sequence

```bash
node scripts/update-vendored.mjs check
node scripts/update-vendored.mjs --diff <skill-name>
node scripts/update-vendored.mjs --upgrade <skill-name>
node .toolkit/scripts/sync-mirror.mjs
node --test scripts/lib/*.test.mjs
node scripts/build-starter.mjs --check
node .toolkit/scripts/check-ai-guidance.mjs --root . --strict
node .toolkit/scripts/sync-mirror.mjs --check
```

`--upgrade` does not delete local additions, but every diff still requires review. Upgrade one Skill at a time when compatibility is uncertain.

## 4. Rebaseline

```bash
node scripts/update-vendored.mjs --rebaseline <skill-name>
node scripts/update-vendored.mjs --rebaseline all
```

Rebaseline is allowed only when local and upstream contents match byte-for-byte after text line-ending normalization. It is not a conflict resolver.

## 5. Offline upgrades

Create a bundle in CI or on a stable network:

```bash
node scripts/update-vendored.mjs --pack bundle
```

Evaluate and apply offline:

```bash
node scripts/update-vendored.mjs --diff <skill-name> --offline bundle
node scripts/update-vendored.mjs --upgrade <skill-name> --offline bundle
node .toolkit/scripts/sync-mirror.mjs
node .toolkit/scripts/check-ai-guidance.mjs --root . --strict
```

## 6. npm packages and host plugins

Review 根目录 manifest 的 packages 字段 and `docs/capabilities.md`, update in an isolated branch, update capability boundaries, run tests/strict validation/mirror checks/Starter build, and record compatibility and rollback. A host plugin is not bundled merely because it is documented.

## 7. GitHub CI

### `ci.yml`

Runs on pushes to `main` and `v*` tags. Ubuntu and Windows with Node 22 run unit tests and strict AI guidance validation. A `v*` tag also checks the version, builds `dist-starter`, packages the ZIP, and creates a Release.

### `vendored-check.yml`

Runs every Monday at 03:23 UTC, on manual dispatch, and on pushes to `main`. It checks upstream versions, uploads a bundle artifact when upgrades exist, and creates or updates an Issue for scheduled/manual runs. Download the artifact and use `--offline` when cloning is slow.

## 8. Commit and rollback

An upgrade commit normally includes 根目录 manifest, `.agents/skills/<name>/`, generated `.claude/skills/<name>/`, related docs, and validation results. Roll back by reverting the commit, then run mirror and quality gates again.

## 9. Prohibited shortcuts

Do not hand-edit `.claude/skills/`, upgrade everything without reviewing diffs, claim an unconnected plugin is available, commit tokens/cookies/proxy credentials, or bypass failures by deleting references or changing exit codes.
