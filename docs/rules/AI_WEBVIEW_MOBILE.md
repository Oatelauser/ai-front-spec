# WebView 与移动端规则层

生效条件：`deliveryTargets` 含 `webview` 或 `mobileH5` 任一为 `user-confirmed` 即载入本文档（由 AGENTS.md 强制入口路由行挂载）；纯移动 H5 项目（无 webview）载入后 `[容器]` 条目按降级语义为背景知识——可见、可参考、不强制、不删除。
本层与框架无关（generic/react/vue 通用）；PWA 不在本层范围。
条目格式：`- [标签] 条文`。标签为封闭枚举三值——`[容器]` / `[视口]` / `[全端]`，禁止第四值。标签决定该条在当前页面是否为硬约束（见「页面声明与判定协议」节）。

## 激活条件表

| 标签 | 含义 | 激活条件（页面 targets 含…） | 典型条目 |
| --- | --- | --- | --- |
| `[容器]` | 页面运行在 WebView 容器 | `webview` | JSBridge 检测、OAuth code 流、旧内核 CSS 兜底 |
| `[视口]` | 移动端视口 | `mobileH5` | safe-area、16px 输入、等比背景坐标系 |
| `[全端]` | 恒适用 | 恒真 | 错误处理集中、安全最小暴露、ObjectURL 释放 |

映射铁律：**标签键名 = `deliveryTargets` 键名**——同一套词，选端时选的是什么，标签激活就查什么，零翻译层、零解释空间。正交不推导：钉钉 PC 内嵌页是 `webview` × 桌面视口，`[容器]` 激活而 `[视口]` 不激活，各查各的键，不做隐含推断。

`tabletWeb` 无专属标签是有意设计：平板归通用响应式规则（断点抽查、宽高约束、连续宽度）管辖，不单设标签。

## 页面声明与判定协议

### 页面声明约定

页面声明取值必须来自 `deliveryTargets` 键名枚举：`browserWeb` / `mobileH5` / `tabletWeb` / `webview`——写枚举外的值按声明错误处理，不做近似匹配。空数组 `[]` 同按声明错误处理（页面至少归属一个端），不视为省略。

```ts
meta: { targets: ['webview'] }                // 仅容器页面：全标签硬约束
meta: { targets: ['browserWeb'] }             // 仅浏览器页面：[容器] 条目豁免
meta: { targets: ['browserWeb', 'webview'] }  // 多端共享页（如登录页）：全标签生效
// 省略 → 缺省跟随项目主端（deliveryTargets 中 user-confirmed 的集合）
```

规则：

1. **缺省跟随主端**：主端含 webview → 全标签生效；主端纯浏览器 → `[容器]` 条目自动降为背景知识（可参考、不强制、不删除）。`[视口]` 条目在纯桌面页面同理降级。
2. **显式声明覆盖缺省**，仅作用于该页面。
3. 页面声明写不进路由生成机制的，落在手写路由 meta 或页面级常量——本文档只约定语义，不绑死实现载体。

### 标签判定协议（四步，frontend-task inspect 阶段执行）

1. **读项目主端**：`.toolkit/profile-state.json` 的 `deliveryTargets`，取 user-confirmed 集合（AGENTS.md 本就强制每阶段读，零新读点）。
2. **读页面声明**：当前任务目标页面的 `route.meta.targets`；缺省 = 第 1 步的主端集合。**第 2 步守卫：声明 ⊄ confirmed 集 → 停**——亮出声明里超出 confirmed 的端，提示用户走 update 流程确认扩端，不静默按扩端执行。任务级确认不适用于本守卫：扩端必须走 update 访谈与矩阵复检，不得以任务内确认放行。
3. **查激活条件表**（上表）→ 得**本页生效标签集**；未激活标签的条目 = 背景知识（可见、不强制）。
4. **生效标签集落纸**：写进 plan 开头一行（如 `本页生效标签：容器+视口+全端`），锚定验收矩阵（acceptance-matrix）行选择步同步产出——选哪些验收行由本页生效标签集决定。落纸才可核对：verify 阶段复查「生效标签 ↔ 页面声明」一致性，写错了看得见。

**分层职责**：AGENTS.md 路由行管第一层（整本文档挂不挂载，按 deliveryTargets 状态）；本协议管第二、三层（条目标签 × 页面声明 → 哪几类是硬约束）。各管一段，不重叠。

**worked example**（照此执行）：

- 项目主端：browserWeb + mobileH5 + webview 全确认
- 页面 A（登录页）`targets: ['browserWeb','webview']` → 生效 = 容器+全端。若登录页还须在手机上显示好，声明里加 `mobileH5`——**声明即事实**，声明里没有的端，对应标签就不激活，不做「应该也算手机吧」的推断
- 页面 B 省略 → 缺省 = 主端全集合 → 生效 = 容器+视口+全端
- 页面 C（钉钉 PC 内嵌）`targets: ['webview']` → 生效 = 容器+全端（PC 是桌面视口，视口不激活）

**多页任务**：逐页判定、逐页落纸——plan 中按页分组列出各页生效标签集（如 `页面A：容器+全端；页面B：容器+视口+全端`），不写整任务单一标签集。

**全局改动**：全局样式、主题或构建配置任务无页面声明——按第 1 步主端全集合判定生效标签集，同样落纸。

## 条目增补生命周期

项目可增补条目：沿用同格式 `- [标签] 条文`，按职责归入对应域。增补条目同样受激活条件表与判定协议管辖；标签仍限三值封闭枚举，不得发明第四值。

## 域 1 视口与全屏

- [全端] 全屏高度统一使用全局全屏高度类（100vh 兜底 + 100svh 覆盖），禁止裸写 svh/100vh 工具类（源：h-app-screen 条）
- [视口] 沉浸式页面 viewport 锁缩放 + viewport-fit=cover；visualViewport 同步只在全局注册一次，单页面不得重复注册（源：沉浸页条）
- [视口] 贴边控件用 safe-area/calc 做边界约束；图标+文案复合控件预留整体宽高防裁切（源：不只以桌面 Chrome 为依据条）
- [视口] 带热点背景保持等比坐标系，禁独立 scaleX/scaleY 与 fill 拉伸；长短屏明确裁切或滚动策略（源：热点背景条）
- [视口] Apple 系设备输入控件字号不小于 16px 防聚焦缩放；placeholder 样式必须作用到真实 input/textarea（源：16px 条）
- [视口] 常见移动视口下页面文字、按钮、图片不得重叠；固定格式区域用明确宽高、比例或 min/max 约束，不依赖内容自然撑开（源：不重叠条）

## 域 2 布局与组件层

- [全端] 常规页/页头/沉浸页优先使用全局布局组件（head/main 结构 + 插槽定制），不自建页面骨架（源：page-layout/page-head/login-layout 条）
- [全端] 统一返回按钮内建空历史判断与兜底路由；返回逻辑先判空历史再 back，有业务入口的页面显式指定兜底（源：BackButton/canGoBack 条）
- [全端] 页面私有组件放页面目录，跨页复用才提升全局；新增 UI 变量/组件先判断归属层级（业务包装层/公共层/基础包/页面私有）（源：组件归属两条合并）
- [全端] 弹窗/抽屉/Toast/Dialog 反馈走项目统一入口，不散落组件库 API；业务反馈走统一消息工具（源：Vant/message 条）
- [全端] 异步确认契约：统一确认入口支持异步 onOk，期间仅确认按钮 loading、失败保持打开，异步期间不禁用取消（源：confirm onOk 条）
- [全端] 布局间距用 gap 配合 flex/grid，不用 space-x/space-y；table-like 结构的水平间距用 border-separate + border-spacing（源：间距条）
- [全端] 不因小改动顺手调整既有 class 顺序，避免产生无关样式 diff（源：class 顺序条）
- [全端] 新增页面前先查页面局部 components/modules/constants/utils，再查全局组件层、业务 UI 层与基础 UI 包，先复用后新增（源：先查局部条）
- [全端] 组件自动注册的范围与例外以项目构建配置为准：注册范围内的组件直接写标签不再局部导入，例外目录局部导入；调整注册范围须同步改构建配置并重新生成组件声明（源：自动注册条通用化）
- [全端] 页头返回事件只做透传；业务要阻止默认返回时显式拦截事件或自定义插槽，并自行处理路由兜底（源：PageHead back 条）
- [全端] 业务态 UI（按钮/弹窗/选择器/选项卡等）优先用项目 UI 包装层，不在业务页直接重复组合底层视觉状态（源：ui 包装层条）
- [全端] 基础 UI 包与业务 UI 层分层清晰：带业务语义的组件进业务 UI 层，无业务语义的通用能力进基础包；共享组件复用基础包公开工具（类名合并、设备判断等）（源：基础包分层条）
- [全端] 局部加载与空态复用公共组件（父容器设 relative，文案与说明走组件入口定制），不散落拼装指示器或空态结构（源：loading/empty 条）
- [全端] 业务域组件优先查对应业务域组件目录，域内复用优先于跨域抽公共（源：业务域组件条通用化）
- [全端] 页面结构变化后按需运行项目的路由生成机制（命令以项目配置为准），不手改生成产物（源：路由生成条通用化）
- [全端] 新增页面后核对生成的路由 name/path/文案键/布局是否符合预期，不符先查生成机制再查页面目录结构（源：核对生成条）
- [全端] 页面私有样式优先 scoped；共享样式或设计 token 变更先查全局影响再动（源：scoped 条）
- [全端] 纯展示文本不用原生 button，用更轻的语义元素；确需 button 承载文字时，文字字号/颜色样式加最高优先级修饰防按钮基础样式覆盖（源：原生 button 条）

## 域 3 请求与认证

- [全端] 请求统一走项目封装层（成功码/Token 头/错误提示集中处理）；业务层不重复 try/catch，不在业务页手写 axios/fetch（源：封装三层分工 + 手写禁令合并）
- [全端] 按封装层返回结构统一解构（如 `{ error, data }`），先判 error 再用数据（源：解构条）
- [容器] 企业容器 OAuth：后端换 Token，前端只收短时 code/state；处理完用 router.replace 清理地址栏敏感参数（源：OAuth + 清参数合并）
- [全端] 认证逻辑复用认证 store 既有 action 链，不另起炉灶；401/登出码走统一登出重置，页面不重复跳转（源：auth store + 401 条）
- [全端] 多页面共用接口数据沉淀全局 store；缓存刷新时机明确（登出、401、切用户必清）（源：store 缓存条）
- [全端] 全局 store 缓存按需刷新：进入关键业务入口、keep-alive 激活、关键业务成功回调后刷新，不靠定时器盲刷（源：缓存刷新条）
- [全端] 二进制类请求（Blob/文件流/图片）通过封装层的请求选项声明 responseType 与 headers 等，返回仍按统一结构解构使用（源：responseType + 第二参数条合并）
- [全端] 登录 Token 的位置以后端契约为准（可能在响应头而非响应体），不假设固定字段路径（源：Token 位置条通用化）
- [全端] 表单字段与后端返回字段保持一致，详情/编辑回显不加中间映射层（源：表单字段条）
- [全端] 新接口在项目统一的手写契约层编写，保持强类型，以后端 Controller/OpenAPI 契约为准（源：手写契约条通用化）
- [全端] 是否显示后端错误提示由封装层配置项控制，业务层不重复 toast、不吞错误（源：错误提示配置条通用化）
- [全端] 历史生成的接口代码视为废弃资产：触达时迁移到项目手写契约层，只迁移不修复、不重新生成、不新增导入（源：生成代码边界条通用化）
- [全端] 不复制后端 DTO 为重复类型；需要扩展时用交叉类型、Pick/Omit 或局部补充类型（源：DTO 条）

## 域 4 安全与最小暴露

- [全端] 后端富文本/评论/用户 HTML/外链/文件名一律按不可信内容处理；富文本渲染走统一清洗组件，不新增裸 v-html（源：不可信 + v-html 合并）
- [全端] token/权限码/租户信息不入 URL/错误提示/前端日志；二维码/订单号等凭证不暴露完整值（源：token 不入 + 凭证条合并）
- [全端] 外链仅允许协议白名单（http/https/mailto），新窗口补 rel="noopener noreferrer"；redirect 仅允许站内相对路径（源：外链 + redirect 合并）
- [全端] createObjectURL 的预览地址在替换/删除/卸载时释放；表单保存后端文件标识，不存 blob URL/base64（源：ObjectURL + 文件 id 合并）
- [容器] WebView 注入的 query/hash/JSBridge 返回值按外部输入处理；code/state/tenantId/corpId 不入日志/Toast/外链/缓存（源：注入参数条）
- [全端] 普通文本、昵称、评论默认纯文本渲染，依赖框架转义，不手动拼 HTML（源：纯文本渲染条）
- [全端] Markdown、活动说明类内容走统一封装的渲染与清洗，不在页面散落清洗配置（源：Markdown 条）
- [全端] 维护已有裸 v-html 页面不盲目扩大改造范围；新增同类渲染必须补清洗逻辑（源：旧 v-html 维护条）
- [全端] 上传前校验文件类型、大小、数量，校验反馈走统一消息工具（源：上传校验条）
- [全端] 导入失败详情为后端文件流时按 Blob 下载处理，不把二进制内容塞进页面（源：导入失败条）
- [全端] 批量导出、删除、核销、兑换、提交类操作前先校验业务状态与权限/登录态（源：批量操作条）
- [全端] 特殊错误提示不展示原始 SQL、堆栈或完整响应体；登录/用户信息/核销类逻辑不打印完整用户对象（源：错误提示条）
- [全端] 业务页不向 console 输出完整接口响应；临时排查用最小信息日志，交付前删除新增日志；作者已有日志不因无关需求删除（源：日志三条合并）
- [全端] 下载文件名用业务名+扩展名，不直接信任用户输入或后端返回的原始文件名（源：下载文件名条）
- [容器] WebView 内打开外链、下载文件、复制内容继续遵守协议白名单、文件名安全与敏感信息最小暴露（源：WebView 外链条）

## 域 5 资源与媒体

- [全端] 设计稿位图按 4x 导出、SVG 保持矢量；高清整屏位图按最大 CSS 尺寸 × DPR（iOS 常 3）核对源像素，压缩不替代源图（源：Figma + DPR 合并）
- [全端] 文件展示优先用直链工具（loading 不等图片），须读 Blob 才用文件流工具并按生命周期释放（源：文件 id 直链条）
- [全端] 动图/动画复用公共播放组件与工具，不引入裸放实现；新资源类型先确认打包归类与缓存策略（源：APNG/PAG 通用化 + 大资源条）
- [全端] 静态资源按业务域放图片目录，资源目录只放资源文件，不新建 TS 文件做资源导出（源：资源目录条）
- [全端] 首屏必载的大图/动图/音视频放预载目录，非首屏资源不入；纳入预载前确认其阻塞启动的格式与边界（源：preload 条）
- [全端] 大资源新增后评估包体与首屏加载影响，只把真正影响进入体验的资源纳入预载（源：大资源条）
- [全端] 本地 SVG 经图标组件使用（symbol 前缀按项目配置），不在页面内联散放（源：SvgIcon 条通用化）
- [全端] 图标优先用项目已有图标库或资源，不为单个按钮手写复杂 SVG（源：图标优先条）

## 域 6 国际化

- [全端] locale 随统一切换入口切换，业务组件使用 i18n 入口导出的翻译函数与 locale 状态，不自行初始化第三方 locale（源：locale 条）
- [全端] 新增文案（页面文案/路由标题/按钮/提示）同步项目全部语言包；公共高频文案进公共命名空间，页面私有文案进页面命名空间，先查重复用（源：文案同步条）

## 域 7 WebView 能力与兼容

- [容器] 企业 WebView 容器一律按能力不完全一致处理（现代 CSS/History/视口/摄像头）（源：容器能力条）
- [容器] 环境判断集中于统一模块并暴露语义函数，不散落 UA 判断；JSBridge/SDK 先存在性/能力检测再懒初始化，页面只调封装（源：两条合并）
- [容器] 旧内核 CSS 兜底集中维护在全局样式入口（translate/color-mix/bg-clip-text/svh/透明遮罩高风险点），不只依赖构建插件自动降级（源：CSS 兜底两条合并）
- [容器] WebView 登录授权页空历史用显式 router.replace/push 兜底，防 back 直接退出容器（源：空历史兜底条）
- [容器] 新增企业容器 CSS 适配时复用或扩展现有兼容插件层，不另建同类插件（源：兼容插件层条通用化）
- [容器] 透明黑遮罩复用全局已兜底的透明度档位；新增透明度或半透明背景用明确色值，避免未兜底的透明色编译产物旧内核不识别（源：透明遮罩条）
- [容器] 弹窗居中定位由弹窗基座内建，业务不重复声明 fixed/translate/transform（防生产构建移除默认值后双重偏移）；关键定位元素用 @supports not (translate) 兜底或显式 transform（源：Dialog 定位条）
- [容器] 渐变+描边标题文字用双层结构分离（描边层 aria-hidden + 填充层渐变），不在同一文字节点叠加透明填充与描边；特定字体走已注册字体变量（源：双层标题条通用化）
- [容器] 目标环境要求严格覆盖旧内核时，评估样式框架版本降级（如 Tailwind v3.4）或补齐明确的全局兼容层，不以「新框架 + 插件自动降级」为唯一方案（源：严格旧内核条）
- [容器] 扫码/摄像头复用公共封装；摄像头枚举不稳定的容器保留后置摄像头兜底与手动输入兜底（源：扫码摄像头条）

## 域 8 验收

- [全端] 交付前 320–450px 多断点 + 连续宽度抽查，尽量真机复核（源：验收抽查条）
- [容器] WebView 适配验收必须包含目标容器真机（模拟器测不出内核差异）（源：真机复核条，新增成文）
- [全端] 移动端页面不以桌面浏览器为最终视觉依据；登录页、沉浸页、全屏背景、固定/绝对定位控件至少按移动视口和目标容器各复核一次（源：桌面依据条）
- [全端] 验收矩阵按本页生效标签集选择对应行执行；verify 阶段复查「生效标签 ↔ 页面声明」一致性，生效标签集写错先修正再过验收（源：判定协议第 4 步联动，新增成文）
